# 2026-08-05 工作日志

## 语音合成升级调研与方案设计
- 用户反馈当前朗读「机械、缺乏自然度」，要求深度调研并给出专业级、优先端侧 AI 模型的语音方案。
- 通读现有语音代码：`src/lib/speech.ts`（Web Speech API 封装）、`src/lib/chant.ts`（平仄/韵脚/情绪 MOOD_TABLE）、`src/modules/poems/poemTrain.tsx`（speakChant 调度）。
- 根因定位：① 一句诗被切成多个独立 utterance，接缝重置破坏连贯（机械感主因）；② 平仄/韵脚/多音字信息全丢（Web Speech 不接受拼音输入）；③ `DeepPoem.lines[].chars[].p` 已有正确拼音但朗读未使用；④ 安卓部分浏览器不支持 speechSynthesis。
- 技术调研：Kokoro-82M（kokoro-js + ONNX Runtime Web，WebGPU/WASM，q4f16≈86MB，Apache2.0，支持中文 zf_001/zm_010）是最现实「端侧神经 TTS」；Piper 中文偏弱；云端 TTS 不符合「设备模型」要求。关键约束：HF 被墙，模型须自托管 Cloudflare。
- 产出方案文档：`docs/语音合成升级方案.md`，含 7 大项（调研对比/问题根因/推荐与备选/集成架构/可调参数/性能体积/分阶段计划+验收）。
- 推荐：Kokoro-82M 端侧主引擎 + Web Speech 兜底；拼音 G2P 解决多音字（诗词用已标拼音、通用用 pinyin-pro）；韵律用句级 speed+WSOLA；自托管模型到 Cloudflare R2 + Cache API；分 P0–P4 实施。
- 状态：方案已交付，待用户确认后进入 P0 验证（含 Kokoro 中文拼音输入格式验证这一关键风险）。
