## 2. 关键发现：构建门禁回归（真实生产阻塞）
- **现象**：`vite.config.ts` 的 `build.modulePreload.resolveDependencies` 回调返回 `(string | { relativeUrl: string })[]`，但 Vite `ModulePreloadOptions.resolveDependencies` 的契约要求返回 `string[]`。
- **后果**：`npx tsc -b` 报 `error TS2769`；而 `npm run build = tsc -b && vite build`，类型检查失败 → **生产构建直接中断 → 无法部署**。
- 该回归在 R1–R7 期间未被发现（`vite.config.ts` 的体积优化为后续追加、且未纳入当时的门禁观察），属于会实际阻断上线的缺陷，原任务明确要求「无需额外调整即可部署至生产环境」，故必须修复。

## 3. 修复内容（仅构建配置，零行为变更、零新模块）
`vite.config.ts`：在过滤后将对象型依赖收敛为其 `relativeUrl` 字符串，使返回类型收敛为 `string[]`：

```ts
resolveDependencies(_filename, deps) {
  // 返回须为 string[]（Vite ModulePreloadOptions 契约）：对象型依赖收敛为其 relativeUrl
  return deps
    .filter((d) => {
      const id = typeof d === 'string' ? d : d.relativeUrl;
      return !/(vendor-three|vendor-opencc|data-poems|vendor-pinyin|data-hanzi|data-languages|data-encyclopedia|confetti)/.test(id);
    })
    .map((d) => (typeof d === 'string' ? d : d.relativeUrl));
},
```

- 运行时语义不变：被排除的依赖依旧不进首屏 `<link rel=modulepreload>`，动态 `import()` 仍即时生效。
- 仅修复类型契约，未改动任何 chunk 划分逻辑与功能代码，符合「禁止引入无关新模块」的约束。
