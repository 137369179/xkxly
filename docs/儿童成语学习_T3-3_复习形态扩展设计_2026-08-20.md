# 成语复习中心 · 形态扩展设计（T-3.3 / V1→V2）

> **相关**：`docs/儿童成语学习功能开发任务清单_2026-08-20.md` — T-3.3（趣味练习矩阵）
> **版本 / 日期**：v0.1-draft / 2026-08-20
> **目标**：把复习中心从单一「含义→猜成语」扩展为多题型「复习/趣味练习」引擎，仍复用现有 SRS 队列与写回，不破坏已交付的复习闭环。

---

## 1. 现状与目标

**现状**：`IdiomReviewCenter.tsx` 每张卡固定为「给含义 → 回忆成语 → 揭晓 → 自评」，自评结果经 `practice(skill, ok)` 写回 mastery；完成整队列发放每日奖励（`completeDailyReview`）。

**目标**：把"一张卡片"抽象为「题型变体」+「如何判定对错」，在不改 `useDueIdiomSkills`（队列）与 `practice`（写回）的前提下，接入多种形态，形成可复用的趣味复习矩阵。

---

## 2. 核心抽象

### 2.1 题型变体
```ts
type DrillVariant =
  | 'recallWord'     // 含义 → 猜成语（现有）
  | 'recallMeaning'  // 词面 → 猜含义
  | 'picGuess'       // 看图 → 猜成语（借助 idiom.image）
  | 'fillBlank'      // 缺字填空（V2，需拆字+干扰字）
  | 'contextPick'    // 场景句 + 4 选项 → 选最贴达成语（V2，需场景句+干扰池）
```

### 2.2 每张卡的结构
```ts
interface DrillCard {
  id: string;          // 复习项标识（skill）
  variant: DrillVariant;
  idiom: Idiom;        // 目标成语
  prompt: ReactNode;   // 题干/线索
  reveal: ReactNode;   // 揭晓内容（答案+图+释义）
  // 客观判定型额外携带
  options?: string[];  // contextPick 的候选（含正确项）
  missing?: number;    // fillBlank 缺字第 index（或数组）
}
```

---

## 3. 两种对错判定（关键差异）

| 分类 | 形态 | 判定方式 | 写回 |
|---|---|---|---|
| **回忆型（自评）** | recallWord / recallMeaning / picGuess | 无法自动判 → 「揭晓 → 记住/忘了」 | `practice(skill, 自评ok)` |
| **客观型（自动判）** | fillBlank / contextPick | 点选选项/填字 → 自动判 | `practice(skill, 自动correct)`，答错再揭晓 |

两者统一收敛：`practice(skill, correct, 0, level) → next()`，故 **SRS 写回、每日奖励、完成逻辑保持不变**。

---

## 4. 组件改造（落点，不改 store）

```
IdiomReviewCenter（保持队列/阶段/奖励）
 └ 每张卡：由 variant 分发到 DrillCard 渲染
    ├ DrillCardRecall   → 回忆型（揭晓 → 记住/忘了）
    ├ DrillCardObjective→ 客观型（选项/填空 → 自动判，错才揭晓）
    └ 每题结束统一走 next() / practice / done
```

- 新增 `variant` 状态：每题进入时按需分配（可随机 / 按进度轮换 / 固定：复习期优先 recall，趣味期优先 objective）。
- `DrillCard*` 拆为独立子组件（便于 `React.memo` 与单测）。
- 渲染探针 `render.card` 保留，可观测不同题型的卡片渲染。

## 5. 分级与验收

### V1（低侵入，先做）
- 形态：recallWord + recallMeaning + picGuess
- 新增：仅 `variant` 状态、`DrillCardReceive/CDriled` 分发、少量 UI
- 数据：`word / meaning / image` 现成
- 验收：
  - 进入复习中心后能看到≥3 种变体交替；
  - 每种变体都能正确「回忆 → 揭晓 → 自评」并写回；
  - 完成整队列后奖励照发。
- 零新增长期类型；均可回退。

### V2（需数据/逻辑）
- 形态：fillBlank + contextPick
- 新增：
  - `fillBlank`：将 `idiom.word` 拆字（4 字成语取一字成空），干扰字取自其它成语的对应位置字（`IDIOMS` 池生成）；
  - `contextPick`：每成语的**场景句**（需静态补充，或先生成默认句）+ 干扰项从另 3 个同难度/非同主题成语取。
- 验收：
  - 客观题型能自动判对错并写回；
  - 干扰项不与正确项重复；
  - 答错后揭晓正确词/句。
- 说明：`contextPick` 的场景句属内容成本，建议单独建数据（可延后立项）。

### 可选：易混辨析（T-3.4）
- 前置 `docs/…任务清单` 的 `T-0.3`：建 `idiomRelated` 易混表 → 出「对比题」（两个易混成语，判异同/选适用）。
- 需要先确认易混对与提示文案。

---

## 6. 复用与不变量（勿破坏）
- 队列来源：`useDueIdiomSkills`（不变量：仍只返回到期的 `idiom:` mastery）。
- 写回：`practice(skill, correct, 0, level)`（难度感知，不变）。
- 每日奖励：走完整队列进 `done` 时 `completeDailyReview(REVIEW_STARS)`（不变）。
- 调试日志 / 兜底开关：新题型沿用 `idrLog('render.card' / 'queue.*' / 'judge.*')` 约定。

---

## 7. 落地建议
1. 先做 **V1**：抽象 `variant` + `DrillCard*`，验证多形态复习闭环；V1 无数据依赖、可回退。
2. **V2** 的 `contextPick` 场景句建议另立内容任务，`fillBlank` 可用生成式干扰先行。
3. 每个变体配单测（至少覆盖：能渲染、能自评/自动判、能写回、完成仍奖励）。
