## 一、现状分析（改造前，实测）

### 1.1 三大核心模块构成

| 核心模块 | 承载目录 | 代表功能 | 既有游戏化元素 |
| --- | --- | --- | --- |
| **识字** | `hanzi`（20 文件）/ `pinyin`（7 文件） | HanziLearn 玩认说练写闭环、WordBuilder 组词造句、HanziDictation 听写、HanziQuizGame | 六书徽章、连击徽章（QuizCard 内置 combo）、星星奖励 |
| **英语** | `letters`（9 文件）/ `words`（13 文件） | LetterOrder 字母排序、WordLearn 单词闭环、CvcWordBuilder、SpellingTest | QuizCard 内置 combo、积分显示 |
| **数学** | `numbers`（24 文件）/ `logic`（4 文件） | MathLadder 十级口算、CountingGame 数数、MathQuiz/MathExtra 题卷、WordProblems 图文应用 | 星级结算、Lv 关卡、动态难度校准 |

### 1.2 改造前关键缺口（竞品对标后判定）

1. **闯关目标感缺失**：除 WordProblems/古诗填字外，核心练习环节均为「一题一过」，孩子看不到「再答对几题就通关」的持续目标；
2. **即时反馈口径不统一**：各模块散落 `sfxCorrect + celebrateSmall + randomPraise` 手写组合，表扬/鼓励语库（`lib/praise.ts` 分 7 场景）未被统一消费；
3. **连对激励未跨题累积**：QuizCard 内部 combo 只提示当前题连击，未形成「3 连对里程碑」的关卡感；
4. **分龄渐进缺乏可视化**：难度按钮存在，但缺少「连对越多难度越具挑战」的即时反馈闭环。

| **宝宝巴士** | 五步标准化流程（象形识形→场景解义→跟读认读→笔顺临摹→随堂巩固）；教材同步；家长管控 | ✅ 闭环已具备；家长报告/进度追踪已有（StreakBar 与 SRS 共用数据源） |

**结论**：头部产品的激励内核可抽象为「**连续正确 → 可视进度 → 达标庆祝 → 错误温和重来**」四步循环。本轮将其落地为可复用组件 `StreakBar`（闯关里程碑条）+ `lib/feedback`（统一即时反馈助手），接入三大核心模块全部题卷式练习。

## 三、改造目标（对齐用户五项游戏化要求）

| 用户要求 | 本轮落地 |
| --- | --- |
| 1) 每个学习功能独立游戏化玩法（积分/闯关/奖励解锁） | 三大模块练习环节全部接入「3 连对闯关」里程碑（StreakBar），点亮圆点即通关，达标自动 Combo 庆祝；既有星星积分/星级结算保留 |
| 2) 渐进式难度设计 | 连对推进过程中 QuizCard 内置 combo 语料升级（general→combo 场景表扬）；各模块既有难度分档（hanzi 拼音/汉字/组词、numbers 5/10/20 内）原样保留 |
| 3) 即时反馈机制（对=积极强化，错=温和引导） | 统一 `answerCorrect/answerWrong` 助手：答对=音效+彩带+分场景表扬，答错=音效+场景温和鼓励（复用既有 praise 语料，不重复造词） |
| 4) 色彩丰富、动画生动 | StreakBar 采用 candy 语义色（黄/绿/紫/粉/蓝）按模块主题渲染；达标触发 Combo 弹簧动画 + 彩带（并行会话已增强） |
| 5) 进度追踪 + 成就系统 | 连对进度实时可见；通关点亮全部圆点并庆祝，形成成长目标感；SRS 回写照常（practice 调用未变） |

## 四、具体实施内容（已落地，8 文件 +126/−10 + 新增 1 测试文件）
