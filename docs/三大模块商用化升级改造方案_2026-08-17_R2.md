### 1.3 本轮修复的两处 CI 阻断红灯（含根因）

R1 记忆将这两处判定为「历史遗留、超出范围」而搁置。本轮复核后**推翻该判定**：二者均为近期提交引入的回归，且直接卡死 CI，商用上线不可能绕过。

#### 🔴 P0-1 导航 emoji 唯一性失败

- **现象**：`src/data/nav.test.ts:52` 期望 37 实得 36。
- **根因**：`NAV_ITEMS` 共 37 项，emoji 🏆 被 `growth`（成长荣誉馆）与 `achievement`（宝贝成就中心）**同时占用**。`achievement` 由最近提交 `3a08369 feat(achievement)` 引入，未检查 emoji 唯一性约束。
- **影响**：侧边栏 / 品类条出现两个视觉完全相同的入口，儿童用户无法区分 —— 属真实体验缺陷，非单纯测试问题。
- **修复**：`achievement` 改用未占用且语义契合的 🏅（已实测确认 37 项全唯一）。

#### 🔴 P0-2 星星回写断言失败

- **现象**：`src/store/useStore.test.ts:51` 期望 `stars` 为 2 实得 7。
- **根因**：`storeHelpers.applyProgress()` 第 113–122 行在每次进度变更后检测新解锁勋章，并调用 `applyMedalReward()` **原地追加奖励星星**（`src/data/medals.ts:300`）。`practice('letter:A', true, 2)` 先发 2 星，随即触发首练类勋章解锁再补发 5 星 → 合计 7。
- **判定**：勋章体系（提交 `dbc7f84`）上线后**测试断言未同步**，属陈旧断言，非业务逻辑缺陷。
- **修复**：将脆弱的「总星 == 2」替换为两条稳定断言 ——
  1. `dailyLog[today].stars === 2`：`bumpLog` 只记录 `practice` 自身发放量，勋章补发不写入 dailyLog，可精确校验；
  2. `progress.stars >= before + 2`：保证回写不丢失，且对未来新增勋章免疫。
  同时补充 `items === 1` / `ok === 1` 断言，覆盖计数回写。

#### 🔴 P0-3 SRS 底座类型错误（并发实例引入，本轮拦截）

- **现象**：`src/lib/srs.ts` 216 / 222 / 228 行报 `TS2538: Type 'undefined' cannot be used as an index type`，共 3 处。本轮 18:33 首次实测为 0 error，18:47 复测变为 3 error —— 由并发实例在 18:44 写入引入。
- **根因**：`skillOrKey.split(':')[0]` 在 `noUncheckedIndexedAccess` 下类型为 `string | undefined`，直接用作 `CATEGORY[key]` 的索引即触发 TS2538。同文件 `subjectColor`（234 行）因只做 `===` 比较、未做对象索引，故未报错 —— 反向印证根因定位准确。
- **影响**：`srs.ts` 是三大模块 SRS 闭环的共用底座，其 `subjectLabel / subjectEmoji / subjectTone / subjectColor` 被家长报告链路消费（`components/charts/StudyCharts.tsx`、`components/MapView.tsx`、`lib/parentAdvice.ts`、`lib/dailyPlan.ts`）。类型检查失败将直接阻断 `npm run build`（build 脚本为 `tsc -b && vite build`），**生产部署完全无法进行**。
- **修复**：抽出类型安全的私有助手 `subjectKeyOf()`，改用 `indexOf` + `slice` 保证返回类型恒为 `string`，四个函数统一复用。同时**消除了该前缀提取逻辑原先在 4 个函数中的重复实现**，并省去每次调用的中间数组分配 —— 一处改动同时解决类型错误、代码重复与微性能三个问题。

**根因建议**：本自动化 rrule 为 `FREQ=HOURLY;INTERVAL=1`，即**每小时触发一次**对同一代码库的「升级改造」。这在工程上必然导致三类问题：
1. **并发写入冲突**（本轮已实测发生）；
2. **重复劳动**（R1 已完成 SRS 闭环，后续轮次需反复辨识「什么已经做过」）；
3. **代码库被高频搅动**，难以形成稳定可发布基线。

> 建议将触发频率调整为**手动触发**或**每日/每周一次**，并在单实例串行执行下推进阶段二至五。
