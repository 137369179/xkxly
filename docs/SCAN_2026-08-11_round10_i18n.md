## 2. 关键工程发现

### 2.1 复用红利（低风险低膨胀）
探查发现 `hanzi` 命名空间此前已为 `HanziLearn` 备齐几乎全部 UI key（listenStory / storyTitle / radical / strokes / strokesCount / toneN / origin / evolve / words / sentence / listenSentence / aiSentence / knowIt / aiRecommend / qPinyin / qHanzi / qWords / strokeWrite / freeTrace / writeInfo / readChar / readWords / readSentence / readDone 等约 30 项）。因此 HanziLearn 仅需补 3 个缺键即完成接线——**字典膨胀极小，覆盖度却最高**。这验证了「先探查现有 key 再接线」的范式价值。

### 2.2 ArtPage 干净重构（功能不变、彻底 i18n）
原 `COLOR_MIXES` 用中文串（如 `'🔴 红色'`）作比较键 + 展示文本一体，导致无法 i18n 颜色名。重构为：
- `type ColorCode = 'red'|'yellow'|'blue'|'white'`；`type ResultCode = 'orange'|'green'|'purple'|'pink'`
- 比较逻辑改为 `m.c1 === newPicked[0] && m.c2 === newPicked[1]`（英文 code 精确匹配，无歧义）
- 展示：`t('art.colors.' + code)` / `t('art.results.' + res)`；结果英文括号用 `RES_EN[res]`（国际通用色名，不参与翻译）

行为与原版 100% 一致（混合规则、成功/失败语音、UI 布局均未变），但颜色名现已随语言切换。

### 2.3 陷阱修复（i18n 接线高频坑）
| 坑 | 表现 | 修复 |
|---|---|---|
| hook 变量名 `t` 与局部 `const t = TONE_STYLE[...]` 冲突 | `t(...)` 被当作 ToneStyle 调用 → "has no call signatures" | `AdventurePage` hook 改名 `tr` |
| `const t = setTimeout(...)` 遮蔽 hook `t` | `t('music.praise')` 报 "used before declaration" | `MusicPage` hook 改名 `tr` |
| `res` 字段类型 | `'orange'` 不属于 `ColorCode` | 新增独立 `ResultCode` 联合类型 |
| `nextLevel.name` / `level.name` 为 `string \| undefined` | 注入 `t()` params 报类型错 | 加 `?? ''` |

> 经验沉淀：**i18n 接线时 hook 命名优先用 `tr` 而非 `t`**，可规避与局部 `t`（定时器/ToneStyle/其它临时变量）的遮蔽冲突——尤其是 `setTimeout` 惯用 `const t`、图表库惯用 `const t`(transform)。
