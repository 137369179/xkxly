# 体积优化审计与实施（R8）

> 日期：2026-08-17 ｜ 项目：宝贝学习乐园（React 19 + Vite 7.1.5 + TypeScript strict）
> 定位：R5 最终报告遗留方向 ②「主包/vendor 体积可进一步拆分」——先量化审计，再落地一个安全优化。

---

## 一、审计方法

1. **全量构建**提取 chunk 清单与大小；
2. **解析 `dist/index.html`** 区分「执行 script」与「modulepreload 预取 link」——前者阻塞首屏，后者仅预取；
3. **引用链回溯**：对每个大 chunk 追查静态/动态引用路径，判定加载时机。

---

## 二、审计结论：体积架构已高度健康

### 1. 既有按需加载基建（审计确认，非本轮新增）

| 机制 | 覆盖对象 | 触发时机 |
|---|---|---|
| 全页面 `React.lazy`（App.tsx 30+ 页面） | 所有功能模块 | 路由命中时 |
| 手动分包 `vendor-three` | three 系 3D 引擎（972KB） | 仅写实猫/星球页（整族同 chunk 防 TDZ 白屏） |
| 手动分包 `vendor-opencc` | 繁简字典（1180KB） | 仅 zh-TW 模式（惰性初始化 + 动态 import） |
| 手动分包 `vendor-pinyin` | pinyin-pro（304KB） | 仅 TTS 链（动态 import） |
| 手动分包 `confetti` | 庆祝彩纸 | 仅首次庆祝 |
| 数据分包 `data-hanzi/poems/languages/encyclopedia` | 大型语料 | 随对应懒加载页面 |

### 2. 首屏真实体积（改造前）

| 项目 | 原始 | gzip |
|---|---|---|
| **首屏执行集**（index + vendor-react + vendor + vendor-motion） | 898 KB | **~310 KB** |
| index.html 静态预取总量（7 chunk，含 2.4MB 按需库） | 2894 KB | — |

首屏执行集 gzip 仅 ~310KB，对 React 19 + 全套 UI 的功能规模属于健康水平。

## 三、本轮实施：modulePreload 精准过滤

### 问题

index.html 静态注入的 `<link rel=modulepreload>` 把 **vendor-three(972KB) / data-poems(787KB) / data-hanzi(187KB) / data-languages(98KB)** 等按需 chunk 全部列入预取清单 → 浏览器首屏预取 **~2.4MB 无效流量**（多数用户从不进入写实猫页/繁体模式）。

### 改动（`vite.config.ts`）

```ts
modulePreload: {
  polyfill: true,
  resolveDependencies: (_filename, deps) =>
    deps
      .filter((d) => {
        const id = typeof d === 'string' ? d : d.relativeUrl;
        return !/(vendor-three|vendor-opencc|data-poems|vendor-pinyin|data-hanzi|data-languages|data-encyclopedia|confetti)/.test(id);
      })
      .map((d) => (typeof d === 'string' ? d : d.relativeUrl)),
},
```

**安全性论证**：modulepreload 仅是「加速提示」——剔除后不改变任何 chunk 内容与动态 import 的运行时按需加载语义，最多让懒页首次进入时多等 chunk 下载（PWA/本地缓存后无感）。

### 效果

| 指标 | 改造前 | 改造后 | 变化 |
|---|---|---|---|
| index.html 预取 chunk 数 | 7 | 3（仅同步依赖） | −4 |
| **首屏 JS 总下载量** | **2894 KB** | **897 KB** | **−1997 KB（−69%）** |
| 首屏执行集 | 898 KB | 898 KB（不变） | 0（渲染无副作用） |

## 四、质量门禁（全绿）

| 门禁 | 结果 |
|---|---|
| `npx tsc -b` | ✅ 0 error（含 vite.config.ts 类型兼容处理） |
| `npx vitest run` | ✅ **626/626**（44 文件，无回归） |
| `npx vite build` | ✅ 构建成功（57–92s） |
| `npm run lint:budget` | ✅ 通过（vite.config 由 linter 自动规范化） |

> 注：vitest/config 的 `PreloadEntry` 类型滞后于 Vite 7 运行时签名，已用「兼容入参 + `.map` 收敛 string 返回」处理，行为以 Vite 7 为准。

## 五、残留建议（未实施，供后续评估）

1. **dist/ 累积产物**：`emptyOutDir: false`（因本机安全工具拦截批量删除而关闭）导致 dist 累积多版本 hash chunk（6 个 index 版本）。建议：CI/服务器部署环境恢复 `emptyOutDir: true` 或执行 `scripts/clean-dist.mjs`（prebuild 已含）确保干净发布。
2. **进一步缩小首屏执行集**（可选，收益递减）：index 575KB 中含全站 UI 组件与 store，可评估将 Sidebar/BottomTabs 等布局按路由懒加载；风险收益比一般，暂不推荐。
3. **data-poems(787KB) 静态引用面**：`ReportExporter`/`questions/index.ts`/`dailyPlan` 等静态引用诗歌库，均位于懒加载页面链内（不进首屏执行），当前合理，无需改动。
