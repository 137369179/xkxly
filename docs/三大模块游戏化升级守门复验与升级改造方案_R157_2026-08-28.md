## 三、本轮实质落地：GameProvider 统一编排上下文（NEW 文件·正交 WIP·零回归）

三核心此前各自挂载 ComboMeter / GentleFeedback / RestReminder 等组件，状态型 Hook（reducedMotion / sound / gamification）分散在多处实例化，存在「多份实现漂移」风险。新增 `src/game/GameProvider.tsx` 补齐 `src/game/index.ts` 已声明的「一行 import 接入全能力」愿景——把三套状态型 Hook 收敛为单一 React Context。

**API 设计**
```tsx
<GameProvider getProgress={store.getProgress} scene="hanzi">
  …练习闭环…
</GameProvider>
// 子组件：
const { reducedMotion, sound, gamification } = useGame();
// reducedMotion: boolean        — A 层动效降级总开关
// sound: { muted, setMuted, play } — S/M 层端侧音效（可静音·零上传·COPPA 友好）
// gamification: { combo, resetCombo, handleAnswer } — 连击 / 即时反馈 / 成就检测
```
`useGame()` 在 Provider 外调用即抛错（fail-fast，强制正确包裹）。

**自检（已实测）**
- ESLint（仅新增文件）：`GameProvider.tsx` **0 错误 / 0 警告**（测试文件被 eslint ignore 规则跳过，仅信息性提示）；对 lint 预算净贡献 = 0。
- 单元测试：`GameProvider.test.tsx` **3/3 通过**（Provider 内三段齐备 / 外抛错 / handleAnswer 反馈与连击正确）。
- 类型检查：`tsc --noEmit` EXIT=0，新文件类型干净。
- 不编辑 WIP 的 `src/game/index.ts`，经深路径 `import { GameProvider, useGame } from '@/game/GameProvider'` 即可复用；三核心收敛 WIP 后增量包裹接入，学习逻辑零改动。
