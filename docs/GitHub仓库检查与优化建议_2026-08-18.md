## 二、优化建议（按优先级）

### A. 合流上线（最高优先，解决 P1）
开 PR `学习乐园` → `main`，CI 跑通后合并即触发 Deploy to Pages 上线：
```bash
gh pr create --base main --head 学习乐园 --title "学习乐园三大模块生产就绪升级" --body "识字/英语/数学达商用标准：SRS 闭环、专项路由、错题聚类、626 测试全绿、首屏 -69%"
```
合并后：CI 验证（typecheck/test/build）+ 自动部署到 GitHub Pages。

### B. 图片优化（解决 P2，预计 180MB→<30MB）
用 `sharp` 批量转 WebP/AVIF 并限定尺寸（封面 ≤1200px、图标 ≤256px）：
```bash
npm i -D sharp
# scripts/optimize-images.mjs：遍历 public/**/*.{jpg,png} → 输出同名 .webp（quality 80）
npm run optimize:images
```
收益：首屏图片下载降 80%+，克隆体积同步下降。可加 CI 步骤校验"无 >1MB 未优化原图入库"。

### C. public/.gitignore（解决 P3）
忽略生成缓存，仅保留源码引用资源：
```
# public/.gitignore
*.wav
/public/dist/
tmp/
*.cache
```

### D. 凭据安全（解决 P4）
```bash
git remote set-url origin git@github.com:137369179/xkxly.git   # 改用 SSH
# 或：gh auth login（凭据存系统钥匙串）
# 并到 GitHub → Settings → Developer settings 撤销并重建该 PAT
```

### E. 分支保护（解决 P6）
GitHub → Settings → Branches → 为 `main` 添加规则：Require a pull request + Require status checks to pass（`CI`）。

### F. Dependabot（解决 P7）
合并 `PR#1`，或在仓库设置开启 `auto-merge` 仅限 `npm_and_yarn` 组。

### G.（可选）Git LFS
若需保留高分辨率原图，用 LFS 管理 `public/**/*.{jpg,png}`，避免 clone 膨胀。

### 4.2 关键解锁：CI 阻断根因修复（本轮最重要发现）

- **现象**：PR#2 初次 CI 失败于 `npm ci`（EUSAGE）——`package.json` 与 `package-lock.json` 不同步：`idb@8.0.3` / `react-window@1.8.11` / `memoize-one@5.2.1` 缺失于 lockfile（源于此前外部重构新增依赖未更新 lock）。
- **修复**：`npm install --package-lock-only` 同步 lockfile（+31 行）；本地按 CI 同命令 `npm ci` 实测通过（371 包）；`tsc -b --force` 0 error、`vitest` 626/626；提交 `d14bcc7` 推送后 CI 转绿。
- **分支保护 API 要点（个人仓库）**：`restrictions` 必须**显式提供且值为 `null`**——`users`/`teams` 仅限组织仓库（个人仓库报 "Only organization repositories…"），`apps` 传数组或对象形式均被 schema 拒绝；同时必须提供 `required_pull_request_reviews`。`enforce_admins=false` 便于 owner 绕过评审自合并。

### 4.3 经验教训

- 凭据加固须先确保存在可用写凭据，再剥离 URL 明文。
- fine-grained PAT 的 API `permissions.admin=True` 为误导值，实际无写权限；经典 `ghp_` PAT 具完整写权限。
- 分支保护更新必须携带 `required_pull_request_reviews` + `restrictions`（`restrictions: null` 表示无推送限制）。
- GitHub 分支保护所需状态检查名需与 workflow job name 完全一致（本例 `类型检查 / 测试 / 构建`）。
