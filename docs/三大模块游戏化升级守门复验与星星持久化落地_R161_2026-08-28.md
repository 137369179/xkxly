## 二、本轮识别的三个真实缺口（代码级证据）

### 缺口 1（P0）：R160 遗留的真实类型缺陷 —— 我自己埋的雷

`src/game/rewardEconomy.ts` 的 `FADE_STAGES` 声明为 `as const satisfies readonly RewardStage[]`，但 `RewardStage` 接口里**没有** `maxMastered` 字段。`satisfies` 会对对象字面量执行多余属性检查，产生 **4 个 TS2353 错误**：

```
src/game/rewardEconomy.ts(159,15): error TS2353: 'maxMastered' does not exist in type 'RewardStage'.
...（162 行共 4 处）
```

R160 的门禁报告记为「本轮 2 文件 0 错误」，**属漏报**——本轮全量 tsc 才暴露。已修复：把 `maxMastered` 收敛进内部类型 `FadeStageRule extends RewardStage`，`satisfies` 目标改为该内部类型。这样 `maxMastered` 作为**查表实现细节**不进入对外契约，未来调整分段不影响调用方签名。

> 全树错误数由此 **14 → 10**（减少的 4 个即本轮修复）。

### 缺口 2（P1，TD-R160-01）：星星经济只有纯函数，没有落盘

`rewardEconomy.ts` 刻意做成纯函数（易测、可复现），但纯函数不留状态——**孩子攒的星星、解锁的奖励、收集册在刷新页面后全部归零**。

研究佐证这不是「小瑕疵」：
- **行业根因归纳**（SUSATEST《Common Data Loss in Education Apps》）：教育类 App 数据丢失的六大技术根因中，本层正面处理四个——状态未跨会话持久化、序列化/反序列化错误、本地存储损坏、应用更新与结构迁移。
- **真实用户代价**：宝宝巴士系「宝宝课堂」的进度归零问题，官方恢复路径只有「绑定账号同步重载」或**客服人工补录**（需提供宝宝昵称、注册手机号、最后正常显示日期、设备型号，12 小时内核查后台日志后回写）。头部产品尚且如此，说明**本地存档自愈能力是必备而非加分项**。

### 缺口 3（P1，NEW）：扭蛋概率是私有常量，无法公示

`RARE_RATE = 0.25` / `EPIC_RATE = 0.05` 是模块私有常量，UI 拿不到，**概率公示与保底计数这两个合规要素都无法实现**。

监管要求（可核验）：
- 《关于规范网络游戏运营加强事中事后监管工作的通知》：**公示必须使用百分比、精确到小数点后两位**；点名违规情形包括「概率数值错误或与实际算法不符」「伪随机导致系统性偏差」。
- **保底机制**：玩家必须能清晰看到距离保底的剩余次数。
- 《广东省消费者权益保护条例》第二十五条：经营者采取随机抽取方式提供商品或服务的，应当以显著方式公示**抽取概率**等关键信息。
- 国际侧（Apple / Google / ESA）：概率公示已是分发前置条件。

> 本产品的扭蛋用「学习赚来的星星」而非现金，严格说不属于付费开箱；但**透明本身就是反操控手段**——ScreenWise 2026《Dopamine-Learning Trap》指出可变比率强化是斯金纳箱的核心机制，而把概率摆到台面上，正是把「惊喜」从黑箱拉回「可预期」。

## 三、本轮落地内容

### 1. `src/game/useRewardEconomy.ts`（NEW · 持久化层）

纯函数 → React 的桥接层，补齐「赚 → 攒 → 花 → 解锁 → 新目标」闭环的最后一环。

**核心取舍：自愈优先于重置。** 大人的工具可以「数据损坏 → 恢复默认」，孩子的乐园不行。攒了两周的星星一夜归零且无法找回，会直接摧毁继续学习的意愿。因此即使读到完全不认识的结构，也**逐字段抢救**能抢救的部分。

| 能力 | 要点 |
|------|------|
| `normalizeRewardState` | 逐字段清洗：非数字/NaN → 默认；负数 → 0；超大值含 `Infinity` → 钳到上界；id 列表与目录求交 + 去重（奖励下架后旧存档不崩） |
| **版本策略** | 存 `version` 字段但**不因版本不符清空存档**——版本号只作未来迁移的分派依据，不是丢弃数据的理由 |
| 跨天翻转 | 只重置「当日入账」，**余额 / 已解锁 / 收集册 / 保底计数全部保留**；日期用**本地日期**而非 UTC（孩子的「今天」由墙上的钟决定） |
| 写盘 | 变更即写；内容与上次一致则跳过（StrictMode 双调用不产生多余写） |
| `degraded` | 复用 `safeStorage` 的 `storage-error` 事件，**存储不可用时游戏照常进行**，仅提示进度可能不跨会话保留——不额外造探测逻辑 |
| 多标签页同步 | 家长中心 + 学习页并存场景；**另一标签页清空时不跟随**，避免一次误触抹掉两处进度 |
| API | `balance` / `lifetime` / `earnedToday` / `owned` / `collection` / `pity` / `odds` / `pityRemaining` / `stage` / `goal` / `stats` / `degraded` + `recordSession` / `unlock` / `drawCapsule` / `resetAll` |
| 状态更新模型 | 「ref 镜像 + 显式 next」而非 setState 回调：同一事件内连续调用（如一节课结束时连记分再抽蛋）不会因批处理读到过期值 |

### 2. `src/game/rewardEconomy.ts`（MODIFIED · 合规补齐）

- 修复缺口 1 的 4 个 TS2353。
- 新增 `capsuleOdds()`：返回三档概率，**与 `rollTier` 共用同一组常量**，从根上杜绝「公示值与算法漂移」这一监管点名违规情形；百分比固定两位小数。
- 新增 `pityRemaining(pity)`：距离触发保底还差几次（已到保底为 0），让保底计数对孩子可见。

### 3. 测试（75 项，全绿）

`useRewardEconomy.test.tsx` 39 项 + `rewardEconomy.test.ts` 36 项（较 R160 +4）：

- **概率与真实频率一致**：蒙特卡洛 20000 次抽蛋，断言各档命中率与公示值偏差 < 3 个百分点（这是唯一能真正防住「公示与实际算法不符」的断言方式）。
- **损坏存档自愈**：字段类型非法 → 只回落该字段，其余照救；非对象 / 残缺 JSON / 版本不认识 → 不崩不清空。
- **跨天**：当日入账归零，其余资产全保留；昨天刷满今天仍能拿星。
- **护栏防回退**：零付费墙 / 零竞争 / 零惩罚话术；余额永不为负；答错也拿得到星；评级星（胜任感反馈）在奖励淡出时永不打折。

### 4. 自测暴露并修复的 2 个真实缺陷（非测试适配）

1. **`toCount` 把 `Infinity` 当成无效值** → 原实现 `Number.isFinite` 判否后回落默认 0，导致保底计数被写成 `Infinity` 时清零，孩子要多抽五次普通档才触发保底。改为区分 `NaN`（无效 → 默认）与 `Infinity`（越界 → 钳到上界）。
2. **测试用例未包 `act`** → setState 延迟刷新，不仅读到旧快照，被延迟的更新还在后续用例才落盘，造成**跨用例状态污染**（表现为「balance 应为 0 实为 4」这类幽灵失败）。全部变更改走 `capture()` 包裹。

> 附带发现：`JSON.stringify(Infinity)` 序列化为 `null`，因此 Infinity 分支无法经 localStorage 触达——测试改为直接对纯函数断言，JSON 路径只覆盖 `-50` / `NaN`。这是诚实反映能力边界，而非放宽断言。
