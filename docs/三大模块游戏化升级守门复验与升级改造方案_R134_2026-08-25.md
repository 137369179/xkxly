## 三、2026 运行性能预算专项研究（新检索）

### 3.1 核心 Web 指标 2026 阈值（Aether / codexguruu / coderfile / digitalapplied 共识）
- **LCP < 2.5s**（感知加载）、**INP < 200ms**（取代 FID，衡量全程响应）、**CLS < 0.1**（视觉稳定）。
- **长任务（>50ms）直接损害 INP**：2026 CrUX 数据显示长任务 < 5 次的页面 INP 达标率 89%，> 20 次仅 23%。
- **首屏 JS 预算**：理想 < 100KB，现实可放宽至 ~200–300KB gzip；第三方脚本预算 ≤ 500KB。
- **代码分割 + 动态 import 是第一杠杆**（本项目已落地）；其余：图片 AVIF/WebP + 显式尺寸（CLS）、字体 `font-display:swap` + 子集化、动画仅用 `transform/opacity`、Web Worker 剥离主线程、长任务用 `requestIdleCallback`/`scheduler.postTask` 拆分。

### 3.2 儿童 App / PWA 性能范式（bigcode / appinstitute / educative / 移动端优化）
- **离线优先 + Service Worker 缓存**：弱网/离线基础功能可用，stale-while-revalidate；骨架屏替代 spinner 提升感知速度。
- **渐进加载 + 资源优先级**：关键功能（登录/核心学习）可在全量资源就绪前运行；非关键资源延迟。
- **性能预算进 CI**：构建若 LCP>2.5s 或包超限即失败——与本项目「五门禁守门」机制同构，可直接复用。
- **竞品印证**：洪恩/宝宝巴士均采 PWA 离线缓存 + 首屏预载；与本项目已具 `sw.js`/`public/sw.js`（WIP 活跃编辑中）方向一致。

## 四、升级改造方案精炼（新增 P 运行性能层）

### 4.1 质量矩阵补全
原任务五大质量维度映射：稳定性(G1·构建闭环) / **运行性能(P·本轮新增)** / 错误处理完备(G3·StruggleModal) / 代码规范统一(lint 基线) / 长期可维护性(Core Loop 架构)。**P 层补齐「运行性能」短板**，使矩阵完整。

### 4.2 P 层具体实施内容（限现有模块 / 构建配置，不回写三核心逻辑）
- **P1 首屏预算固化**：CI 新增性能预算门禁，将本轮回测值（首屏 ≤ 245KB gz、无 >900KB 急加载块）固化为基线，回归即阻断。
- **P2 opencc 按需瘦身**：繁简转换改为动态 import + 仅加载目标方言字表，将 1.18MB 拆为按需子块，避免一次性拉取 506KB gz（切换方言时增量 < 200KB）。
- **P3 three.js 子模块 tree-shaking**：仅导入所用几何体/材质，避免整包 972KB 入 lazy 块。
- **P4 字体与图片治理**：全站 `font-display:swap` + 中文字形子集化；PNG/插画资源转 WebP/AVIF + 显式尺寸（CLS<0.1）；首屏骨架屏替代加载圈。
- **P5 长任务治理**：批量计算/动画用 `requestIdleCallback`/`scheduler.postTask` 拆分，主线程 INP<200ms；触摸命中区维持 ≥44px。
- **P6 PWA 离线优先**：Service Worker 缓存静态资源 + stale-while-revalidate，弱网/离线可学（复用现有 `sw.js`，不重写三核心）。
- **P7 RUM 监测**（超范围待授权）：`web-vitals` 采集 LCP/INP/CLS 上报，生产环境真实感知。

### 4.3 验收标准（P 层 7 项 + 继承）
1. 首屏 JS gzip ≤ 250KB（当前 245KB ✅ 维持不增）
2. 无 >900KB 急加载 chunk（当前 0 ✅）
3. 实验室 LCP<2.5s / INP<200ms / CLS<0.1
4. opencc 按需加载后首屏不增、切换方言增量 < 200KB
5. 构建 EXIT=0 / tsc0 / vitest≥1000 / lint 预算通过（继承 G/L/S 全部门禁）
6. PWA 离线首屏可交互（Service Worker 缓存命中）
7. 性能预算门禁进 CI，回归自动阻断
