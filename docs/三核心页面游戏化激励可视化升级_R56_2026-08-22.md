## 三、具体实施内容（3 文件 +1 测试文件，零逻辑改写）

### 3.1 新增可复用组件 `src/components/study/ModuleGameCard.tsx`
- 纯 UI、零副作用；props：`emoji/title/desc/progress(0-100)/masteredCount/totalCount/stars/tone/locked/onEnter/testId`。
- 复用既有 `ProgressBar` + `cn`；`motion.button` 提供 hover 放大 / tap 缩放回弹。
- 渲染逻辑：掌握度进度条 + 「已点亮 N/总数」或「进度 N%」或「还没开始哦」+ 星星数（仅 >0 且未锁定时）+ 🔒 锁定态。

### 3.2 英语 `LettersPage.tsx`（UI 接入，零逻辑改动）
- 主入口 Tabs 改为 **2×3 游戏化功能卡网格**：字母墙 / 字母精学 / 描红 / 排序 / 字母游乐场。
- 进度源自 `masteredCount(progress,'letter:')` / 26 与 `useStars()`；游乐场卡在 `lettersDone>=8` 前置下解锁，否则 🔒 并显示「学会 8 个字母解锁」。
- 移除仅用于主导航的 `Tabs` 导入（交互逻辑由卡片 `onEnter→setTab` 承接，零回归）；arcade 二级切换保留在 Suspense 内按钮组。

> **【事后澄清 · 2026-08-28 审计】** 本节 5 张卡**共用同一份全局字母进度**（`masteredCount(progress,'letter:') / 26`），并非「每张卡各自独立计算进度」——字母子功能（字母墙 / 精学 / 描红 / 排序 / 游乐场）本质上是对**同一批 26 个字母**的不同练习方式，SRS 仅按 `letter:*` 单键记录掌握度，不存在可区分的子维度。此为**有意的设计取舍**，非缺陷。
>
> 因此上方「用户要求对照表」第 ① 行的「入口卡各自展示进度条」应理解为「各自展示**与其相关的**进度」，而非「各自独立计算」。若未来要真正做到逐卡独立进度，需先为各子功能建立独立的 SRS 回写维度——属**数据层改造**，超出本轮「入口 UI 层零逻辑改写」的严格隔离范围，故未纳入。

### 3.3 数学 `NumbersPage.tsx`（UI 接入，零逻辑改动）
- 二级标签栏改为 **游戏化功能卡网格**（按分类 2/3/5 列自适应）：每卡显示该子功能进度。
- 进度计算：已知回写前缀的子功能（tenframe/trace/skip/math/extra/vertical/ladder/run/word/shape/fraction/money）用 `math:<key>` 掌握计数 / 6 小目标；未独立回写者（wall/speed/clock/measure）用所在分类已回写子功能占比聚合——**全部真实、无虚构**。
- 接入全局 `useStore(s=>s.progress.stars)` 作为星星展示。

> **【事后修正 · 2026-08-28 PR #20】** 上述进度算法经审计发现缺陷，已由 PR #20（squash 提交 `6027570`）修正。**以本注解为准，上方原文仅作历史记录留存**：
>
> - **原缺陷**：采用精确匹配 `k === key` 且除以常量 `6`。但 `trace` 实际回写 `math:trace:0..9`、`ladder` 回写 `math:ladder:1..8`（**带子项后缀的键**），精确匹配永远命中不到 → 这两张卡**恒显 0%**；其余单键技能（tenframe / skip / 加减…）上限卡在 **17%**，永远无法达到 100%。
> - **附带问题**：`vertical`（竖式进位）组件**根本不回写任何 SRS 键**，原文将其映射到 `math:add` 属**假相等**，会被错误等同为「加法」的进度。
>
> **当前实现**：
> - 抽出纯函数 `calcMathSubProgress`（`src/modules/numbers/mathProgress.ts`），改用**前缀匹配**（可命中 `math:<key>:N` 子项键）+ **平均掌握等级 / MAX_LEVEL**，进度 0–100 平滑可饱和。
> - `vertical` 已从映射表移除，改走**算术分类聚合**近似。
> - 配套单测 `mathProgress.test.ts`（11 例）覆盖上述行为，防止回归。
>
> 完整审计见 `docs/pr-19-review-2026-08-28.md`。
