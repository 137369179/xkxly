## 自动化发现（按类别）

### 🟡 NEEDS ATTENTION（功能正确性）

**F1 · NumbersPage 进度计算逻辑缺陷——进度条实际只能显示 0% 或 17%，永不饱和**
- 文件：`src/modules/numbers/NumbersPage.tsx`（`subProgress` 内 `calc`，约 L143–152）
- 代码：
  ```ts
  const done = Object.keys(mastery).filter(
    (k) => k === key && (mastery[k]?.lv ?? 0) >= 1
  ).length;
  return Math.min(100, Math.round((done / 6) * 100));
  ```
- 问题：`mastery` 以技能 id 为键，`k === key` 精确匹配，**`done` 取值域为 0 或 1**。再除以 6，进度只能是 `0%` 或 `17%`（1/6≈0.167）。即便某技能已练到 lv5，`done` 仍为 1，进度恒为 17%。
- 影响：所有「具体技能回写」子功能卡的进度条实质是二值指示（未开始/已开始），与「掌握度进度」语义不符，且永远无法显示 50%/100% 等真实进度。
- 修复建议：若模型为每个子技能含 6 个微目标，应改为统计该键下 `lv>=1` 的微目标数量（如 `Object.keys(mastery).filter(k => k.startsWith(key)).length` 或按实际数据建模）；否则直接以 `lv` 等级映射进度（如 `min(100, lv/5*100)`）。需先确认 `mastery` 的真实数据结构。

**F2 · NumbersPage `SUB_MATH_KEY` 映射碰撞——`math` 与 `vertical` 指向同一 mastery 键，进度被重复/串味**
- 文件：`src/modules/numbers/NumbersPage.tsx`（约 L120–135）
- 代码：`math: 'math:add'` 与 `vertical: 'math:add'`
- 问题：「加法(math)」与「竖式(vertical)」两个不同子功能卡引用同一个 `math:add` 掌握度键，二者进度恒等。竖式进度被错误等同于加法进度，属数据串味。
- 影响：可视化误导（竖式关卡显示的是加法进度）。
- 修复建议：为 `vertical` 单独建立回写键（如 `math:vertical`），或在未独立回写时明确走「分类聚合」分支而非复用他人键。

### 3. 关键网络/凭证结论（供后续会话复用）
- 本机双代理：环境变量 `HTTP_PROXY=127.0.0.1:54674` 会将 `api.github.com` **301 跳转到 github.com**（REST 经此全死）；git 专用 `http.https://github.com.proxy=127.0.0.1:3068`（= `CLOUDSDK_PROXY_PORT`）**可正常转发 `api.github.com`**。解法：`curl -x http://127.0.0.1:3068 ... api.github.com`。

- 令牌分层：`GH_TOKEN`/`GITHUB_TOKEN`（细粒度 PAT）仅 `Contents` 权限，**缺 PR / Administration**；`git credential fill`（osxkeychain）取出的**经典 PAT `ghp_…`** 具 repo+admin 全权限，建 PR / 合并 / 改保护均用它。
