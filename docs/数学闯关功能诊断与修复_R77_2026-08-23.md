## 四、关键修复 [FIX-M1]：setTimeout 内存/逻辑隐患

**问题**：`handleSelect` 中 `setTimeout(() => nextQuestion(), 1600)` 存在两处确定性缺陷：

1. **卸载后 setState**：组件在 1.6s 等待期内被卸载（切换子标签/页面）时，定时器仍触发 `nextQuestion()` → 对已卸载组件 setState（React 警告 + 无谓渲染）。
2. **旧题覆盖新题**：在答题等待期内快速切换难度 `mode`，`useEffect([mode])` 已用新 `mode` 出题，但旧 `setTimeout` 闭包捕获的是**旧 `mode`**，1.6s 后会用旧模式题目覆盖刚生成的新题。

**修复方案**（最小化、符合 React 规范，零业务逻辑改动）：

```tsx
// 1. 引入 useRef
import { useState, useEffect, useRef } from 'react';

// 2. 持有待处理计时器引用 + 清理函数
const nextTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);
const clearPendingTimer = () => {
  if (nextTimerRef.current !== null) {
    clearTimeout(nextTimerRef.current);
    nextTimerRef.current = null;
  }
};

// 3. effect 在切模式/卸载时清理挂起计时器
useEffect(() => {
  nextQuestion();
  return clearPendingTimer;
}, [mode]);

// 4. 出题前先清理，防止重复出题
const nextQuestion = () => {
  clearPendingTimer();
  const q = generateQuestion(mode);
  // ...
};

// 5. 将计时器句柄存入 ref
nextTimerRef.current = setTimeout(() => {
  nextQuestion();
}, 1600);
```

**修复后行为**：
- 组件卸载 / 切难度时旧计时器被立即清除，杜绝卸载后 setState 与旧题覆盖。
- 同一时刻仅有一个挂起计时器，出题逻辑互斥。
