# 线上 404 故障诊断与修复报告

- 日期：2026-08-10
- 站点：`xkxly.ccwu.cc`（Cloudflare Worker `baobei-bff` 自定义域名）
- 现象：用户反馈「网站打开显示错误」
- 结论状态：✅ 已修复并验证

---

## 1. 故障现象（错误现象描述）

```
$ curl https://xkxly.ccwu.cc/
HTTP/2 404
content-length: 0
content-security-policy: default-src 'self'; script-src 'self' 'unsafe-inline'; ...
server: cloudflare
```

- 运行环境：生产环境 Cloudflare Workers（`baobei-bff`）+ Workers Assets 静态托管。
- 复现步骤：浏览器/HTTP 客户端直接访问站点根路径 `/` 即返回 404 空响应。
- 预期行为：返回 200 并加载 `index.html`（React 单页应用入口）。
- 实际行为：返回 404、body 为空，页面无法打开（即用户描述的「显示错误」）。

---

## 2. 根因定位

### 2.1 直接原因
Worker 配置了 `[assets]` 绑定（`directory = "../dist"`，`not_found_handling = "single-page-application"`）。
404 响应头带 `_headers` 中的 `content-security-policy`，证明请求**确实打到了 Worker 的 ASSETS 绑定**；
但 ASSETS 在 `dist/` 中找不到 `index.html`，SPA 回退因无首页文件而失败 → 404。

### 2.2 根本原因（构建未产出应用）
本地 `dist/` 目录**只有 `public/` 的静态文件**（`*.jpg`、`icons/`、`sw.js`、`manifest.json`、`_headers` 等），
**没有 `index.html`，且 `dist/assets/` 为空目录（0 个文件）**。

构建链 `npm run build` = `prebuild`(clean-dist + gen-sw-precache) → `tsc -b && vite build`：
1. `prebuild` 的 `clean-dist.mjs` 删除了旧的 `dist/assets` 与 `dist/index.html`；
2. `tsc -b`（**未加 `--force`**，依赖增量缓存 `.tsbuildinfo`）在陈旧缓存下报出 **2 个幽灵类型错误**：
   - `IdiomChain.tsx(71)` 「Expected 1 arguments, but got 2」——源码 `idiomHintTask(lastChar, usedIdioms?)` 本就接受 2 参；
   - `BeatTap.tsx(96)` 「Not all code paths return a value」——实为陈旧缓存误报；
3. `tsc -b` 非零退出，被 `&&` 短路 → **`vite build` 从未执行** → 没有 `index.html`、没有 `assets`；
4. 部署把这份「缺应用」的 `dist/` 上传，线上自然 404。

> ⚠️ 诊断反模式：此前一轮用 CDP 抓取「零运行时异常」被误判为修复成功，实则 CDP 加载的是 404 空页（无 React 自然无 JS 报错）。**404 ≠ 无前端错误**，验证必须以真实 HTTP 状态 + 入口资源为准。

---

## 3. 修复措施

| 步骤 | 操作 | 结果 |
|------|------|------|
| 1 | `tsc -b --force` 清增量缓存 | 幽灵错误消失，仅剩 1 个**真实**错误 `FillBlank.tsx(241)`（`selectedIdx: number | null` 作数组下标 → TS2538） |
| 2 | 修 `FillBlank.tsx(241)`（linter 改为先判空：`answered && selectedIdx !== null ? question.options[selectedIdx] : '???'`） | `tsc -b --force` 再次运行 → **0 错误** |
| 3 | `npm run build` | `BUILD_EXIT=0`；生成 `dist/index.html`(1749B) + 133 个 `assets`，含 `vendor-react-C9F-5wKr.js`（React 19 跨 chunk `Activity` 崩溃修复已随构建打入） |
| 4 | `wrangler deploy`（沙箱外 + `env -u` 清代理） | Version `55470565-f302-4629-9397-701fb51d7cc7`，上传 130 assets，`env.ASSETS` 绑定正常 |

辅助修复（上一轮已完成、随本次构建一并上线）：
- `vite.config.ts`：`resolve.dedupe: ['react','react-dom','scheduler']` + 精确 `manualChunks`（react 全家桶同置 `vendor-react`），根治 React 19 跨 chunk `Cannot set property 'Activity' of undefined` 白屏。
- `src/modules/pet/CatHousePage.tsx`：`Outfit` 接口补 `emoji` 字段。

## 5. 长期加固（可维护性）

写入项目记忆 `MEMORY.md` 的构建门禁铁律：
1. **`tsc -b --force` 是唯一可信的类型闸门**——增量缓存会同时掩盖真实错误、制造幽灵错误；
2. `npm run build` **严禁管道到 `tail`** 掩盖失败；
3. `wrangler deploy` 必须 `dangerouslyDisableSandbox` + `env -u HTTP_PROXY -u HTTPS_PROXY -u NO_PROXY`。

建议（可选，未执行）：在 CI 中把 `npm run build` 替换为显式 `tsc -b --force && vite build`，从源头杜绝幽灵错误导致漏构建。
