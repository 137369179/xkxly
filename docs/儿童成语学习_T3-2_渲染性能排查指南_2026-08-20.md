# 成语 SRS 复习中心 · 真实浏览器渲染性能排查指南

> **模块**：`IdiomReviewCenter.tsx`（T-3.2 SRS 复习中心）
> **版本 / 日期**：v1.0 / 2026-08-20
> **目的**：结合内置日志埋点，在**真实浏览器**中用 Performance/Console 定位「多余重渲染 / 慢渲染 / 无谓子组件重绘」，为后续优化（如 `React.memo`、依赖拆分）提供依据。

---

## 1. 内置埋点说明（回顾）

所有日志通过 `idrLog(stage, payload)` 输出，带紫标 `[IdiomReview]` 与相对时间戳 `t_ms`，由 `idiomReview_debug` 开关控制，**默认关闭、零输出开销**。

| 日志 | 触发时机 | 关键字段 | 用于判断 |
|---|---|---|---|
| `mount` | 组件挂载 | dueSkills / queue | 进入复习中心 |
| `queue.ready` | 队列就绪/变化 | queue(id 列表) | 队列来源与重算 |
| `stage.reveal` | 点「揭晓答案」 | word | 交互是否触发 |
| `judge.remember/forgot` | 自评 | skill/word/level | 写回是否发生 |
| `progress.next/done` | 换题/完成 | from/completed | 流程推进 |
| `render` | **每次渲染** | n、since_ms、phase/index/current/queueLength | 渲染次数与间隔 |
| `render.commit` | **提交到屏幕后** | n、dur_ms、phase/index/current | 单次渲染耗时 |
| `render.card` | 卡片 `ReviewCard` 渲染 | word、n | 卡片是否被无谓重绘 |

> 字段说明：
> - `n`：组件实例累计渲染序号（`render.card` 的 `n` 为该卡片自己的计数）。
> - `since_ms`：距上次 `render` 的毫秒数（`-1` 为首帧）。
> - `dur_ms`：本次渲染起点→提交后 的近似耗时。

## 2. 前置：开关与操作路径

```js
// 开启日志
localStorage.setItem('idiomReview_debug', '1')
// 关闭日志
localStorage.removeItem('idiomReview_debug')
```
> 说明：`isIdrDebug()` 已含「绕过 safeStorage 直接回读 `window.localStorage`」的兜底，用它直读也生效；Safari 隐私/禁用存储时回 false（不抛错）。

**目标路径**：成语故事屋 → 库页顶部「🔁 复习中心」入口 → 进入复习（回忆→揭晓→自评）。

---

## 3. Chrome DevTools 实操步骤

1. 打开页面进入复习中心，Console 里开启开关。
2. **Console** 先看日志是否逐帧打印（确认调用链正常）。
3. 打开 **Performance** 面板 → 点 🎞 录制。
4. 正常操作：进入复习 → 来回「回忆/揭晓/自评」数张 → 停止录制。
5. 分析 Performance 的 **Main** 分段：
   - 定位每次点击后的 "Render/Recalculate Style/Paint"；
   - 看 `render.commit` 的 `dur_ms` 是否有明显尖峰；
   - 若频繁出现"不该有的 Render"，回 **Console** 对照 `render #n` 的 `since_ms` 是否密集（说明无谓触发）。
6. 对照下表的判定规则。

---

## 4. 判定规则（日志 ↔ 问题）

| 观测 | 判定 | 处置方向 |
|---|---|---|
| 无操作时 `render` 的 `n` 还在连续上升 / `since_ms` 极小 | **多余重渲染** | 检查订阅范围；`practice` 回写是否不该触发本组件渲染；减少父级状态变化 |
| `render.commit` 的 `dur_ms` 明显 > 其它（尖峰） | **慢渲染** | 拆分大组件 / 推迟非关键计算 / 检查 `motion` 或重图渲染 |
| `render.card` 的 `n` 上升但 `word` 未变 | **子组件无谓重绘** | `React.memo(ReviewCard)`，或把依赖 props 收窄 |
| `queue.ready` 在每次渲染都被触发 | **队列计算重复** | 把 `queue` 关联的 useMemo/useShallow 选择器稳定化 |
| 点自评后大量 `render` 连续（1 次交互→多次冲突渲染） | **过多 commit** | 合并 setState / 用 reducer 一次性更新 |

---

## 5. 常见优化建议

- **`ReviewCard` 无谓重绘**：`React.memo` 包裹，props 只传 `idiom` 引用不变的数据。
- **父级订阅过宽**：复习中心只应该订阅 `dueSkills` 与 `practice/learnSkill`（已用 `useShallow` 细粒度）；避免订阅整块 `mastery`。
- **队列重算**：`queue = useMemo(()=>..., [dueSkills])`；确保 `useDueIdiomSkills` 返回引用稳定（`useShallow`）。
- **交互合并渲染**：自评一次仅 `practice + learnSkill + next`，避免在 `next` 内再叠 setState 造成多 commit。
- **日志本身**：默认关闭零开销；排查时再开。切勿在 `render()` 内做重计算。

## 6. 收尾

```js
localStorage.removeItem('idiomReview_debug')
```
- 确认优化前后：对比「同一套操作」的 `render.commit(dur_ms)` 累计、`render #n` 总数。
- 若需长期保留内嵌埋点，保持默认关闭即可；如需移除全部埋点，删除 `idrLog`/`isIdrDebug` 及各处调用即可。
