# 识字模块专业增强方案与开发设计

> 版本 v1.0 · 2026-08-11 · 状态：研究完成，待开发设计确认
> 适用工程：`宝贝学习乐园`（React 19 + TS + Vite 7 + Tailwind v4 + Cloudflare Worker）
> 本文档遵循「先研究、专业级分析、再做开发设计」的推进顺序。

---

## 0. 执行摘要（TL;DR）

识字模块**当前完成度已属国内儿童识字 App 的第一梯队水准**：已具备「玩-认-练-写-说」五步学习闭环、自适应难度（DDA）、SRS 间隔重复、TTS 神经语音朗读、AI 字理故事生成、真实笔顺动画（hanzi-writer-data，9000+ 字）、7 类题型、字族/部首/听写/演变/组词等子工具、300 字三阶字库。

经对全网头部产品（洪恩/悟空/叫叫）、国际方案（Heisig/WaniKani/Skritter/Chineasy）、学术教学法（六书/字理/集中识字/字族文）与开源数据源（hanzi-writer / Make Me a Hanzi）的系统研究，本方案确定**三大专业增强杠杆**——这三点是现有架构尚未覆盖、且能显著拉开专业差距的关键：

| 杠杆 | 一句话 | 教学法依据 | 对标 |
|---|---|---|---|
| **① 六书字理分类** | 给每个字打上象形/指事/会意/形声标签，构建「按字理讲字」的分类主线 | 字理识字法、六书 | 洪恩「字理动画」、Chineasy |
| **② 部件派生图（基本字带字）** | 独体字 → 加部件 → 派生合体字，串成可视化「字族网络」 | 集中识字·基本字带字、部件识字 | WaniKani radical→kanji 依赖图、Heisig 部件建构 |
| **③ 真·字形演变 SVG** | 甲骨文→金文→小篆→楷书的**真实字形图**（而非现有纯文字描述） | 字源识字、多感官记忆 | 洪恩演变动画、汉字叔叔字源库 |

三者均**深度复用现有基础设施**（SRS 的 `hanzi:${c}` skill、adaptChain 的 `hanzi:` 类别、TTS `speak`、PWA 离线预缓存、ai/guard 儿童安全护栏、i18n 双语），不做重构、不新增独立子系统——符合「一能力一入口、删优于增、基于现有系统迭代」的维护总纲。

## 1. 全网深度研究结论

### 1.1 儿童识字教学法（学术 / 教研层）

汉字教学在中国大陆有成熟的教研体系，核心流派与本模块的适配度如下：

| 教学法 | 核心思想 | 代表 | 对低龄儿童适配度 | 本模块可吸收点 |
|---|---|---|---|---|
| **字理识字** | 按汉字构造规律（六书）讲解，"知其所以然" | 贾国均 | ★★★★★ | 六书分类主线（杠杆①） |
| **集中识字·基本字带字** | 先学独体基本字，再"带出"同族合体字（青→清晴请睛情） | 辽宁黑山 | ★★★★★ | 部件派生图（杠杆②） |
| **分散识字** | 字不离词、词不离句、句不离篇 | 斯霞 | ★★★★☆ | 已有：例句 sentence + 组词 words |
| **字族文识字** | 同一母体字构成的字族编成韵文 | 鄢文俊 | ★★★★☆ | 已有 family Tab，可强化 |
| **韵语识字** | 用韵文/儿歌承载生字，朗朗上口 | 姜兆臣 | ★★★★☆ | 复用古诗模块 + speakChant |
| **多感官识字** | 视（字形）+ 听（读音）+ 动（书写）多通道 | 蒙台梭利延伸 | ★★★★★ | 已有：动画+TTS+描红，可加字源图 |

**关键实证结论（可直接指导选字与排序）：**
- **象形字、指事字的低龄辨识率最高**（台师大研究）——应作为启蒙阶段主力，并优先呈现字源图。
- **高频字 + 成字部件优先**：约 319 个部件参与构字，掌握高频成字部件可迁移识别大量合体字。这是"基本字带字"的量化依据。
- **认读先于书写、独体先于合体、基本笔画先于复杂笔画**——本模块 level 分级已部分体现，可用"部件依赖图"进一步强化排序。
- 循字项目提炼的"128 教学核心字"（象形 86 / 指事 14 / 会意 26 / 形声 2）可作为杠杆①②的**首批落地字集**。

### 1.2 国内头部产品拆解

| 产品 | 学习流程 | 字量 | 特色 | 短板 | 我们已有对标 |
|---|---|---|---|---|---|
| **洪恩识字** | 玩→认→练→写 四步 | 1300（三阶） | 字理动画、字卡、书写、日报/周报雷达图 | 付费墙、内容重 | ✅ 五步流（多"说"）+ 家长报告 |
| **悟空识字** | 初识-巩固-跟读-听音-辨音-组词填空 六步 | 1200 | 西游记 IP 故事线、辨音强 | **无书写** | ✅ 有书写描红（超越） |
| **叫叫识字** | 认-巩固-跟读-动画-复习 | — | 冒险故事线、复习闭环 | 字理弱 | ✅ 有 SRS 复习 + AI 故事 |

**洞察**：头部产品的护城河是**「字理动画 + 系统化字卡 + 数据化报告」**。我们已有 AI 字理故事（文字）+ 报告，**唯独缺「可视化字理」**——即字形演变图与部件拆解图。这正是杠杆①③要补齐的。

### 1.3 国际方案（汉字/日语汉字学习）

| 方案 | 机制 | 优点 | 缺点（业界批判） | 借鉴 |
|---|---|---|---|---|
| **Heisig《Remembering the Hanzi》** | 部件→字系统建构，用助记故事 | 部件复用、系统性强 | **无拼音、无词汇、顺序静态** | 部件建构思想（杠杆②），但补拼音+组词 |
| **WaniKani** | radical→kanji→vocabulary 三层，**自动 SRS** | 依赖图清晰、含读音词汇 | 顺序固定、偏日语 | **依赖图驱动 SRS 解锁**（杠杆②+SRS） |
| **Skritter** | SRS 驱动**书写**肌肉记忆 | 书写记忆强 | 重、偏进阶 | 已有描红，可加 SRS 到期书写复习 |
| **Chineasy** | 象形图形化记忆 | 视觉美、启蒙友好 | 覆盖字少、不系统 | 象形字配图（杠杆① + 字源图） |
| **Sensible Chinese** | 批判 Heisig，主张先 200 字再组 500 词 | 平衡认读与应用 | 方法论非产品 | 分级 + 组词已覆盖 |

**洞察**：WaniKani 的 **radical→kanji 依赖图驱动解锁**是最值得借鉴的机制——把"先学部件、再学合体字"用**数据结构（precursor 图）**固化，让 adaptChain/SRS 沿依赖图推荐下一个字，比现有 `nextHanzi` 的线性遍历更专业。

### 1.4 开源数据源对比（决定杠杆③的技术选型）

| 数据源 | 覆盖 | 内容 | 许可 | 用途 |
|---|---|---|---|---|
| **hanzi-writer-data** | 9000+ 字 | 楷书笔顺 SVG path + median 点 | MIT | ✅ 已用于描红/演变第4帧 |
| **Make Me a Hanzi** | 9000+ 字 | `dictionary.txt`（字源 etymology + 部首 + 拆分 decomposition）+ `graphics.txt`（笔顺 SVG） | Arphic 宽松许可 | **杠杆①②数据来源**：六书线索、部件拆分、字源文本 |
| **汉字叔叔字源库 / 象形字典** | 数千字 | 甲骨文/金文/小篆真实字形图 | 需确认许可 | 杠杆③理想图源（需评估版权） |

**技术决策**：
- **六书类型 + 部件拆分** → 优先用 **Make Me a Hanzi 的 `dictionary.txt`** 自动抽取（`decomposition` 字段用 IDS 描述结构，`etymology` 字段含 type: pictographic/ideographic/pictophonetic），人工校订首批 300 字。
- **字形演变图** → 甲骨文/金文/小篆真实图存在版权风险，**第一期采用「程序化 SVG 演变示意」**（用 hanzi-writer 楷书 + CSS 形变/描边动画表现"从古到今"的书写过程），第二期再评估接入公有领域字源图（如维基共享资源的甲骨文字符）。这样离线优先、零版权风险、可立即落地。

## 2. 现有模块能力基线（Baseline）

摸清代码后，识字模块现状如下（**这些不需要重做，是增强的地基**）：

**入口与信息架构**（`src/modules/hanzi/HanziPage.tsx`，11 个 Tab）：
```
level1/2/3  启蒙/常用/进阶 字墙（点字进入学习流）
dictation   听写      family    字族
worksheet   字帖       radical   部首
magic       部首魔法(RadicalsMagic)
h500        字库       evolve    演变(HanziEvolve, 目前基于文字 evolve 字段)
builder     组词(WordBuilder)
```

**单字学习流**（`HanziLearn.tsx`，五步 `FlowStep[]`）：
`play`(AI 字理故事) → `know`(字理+组词+例句) → `practice`(难度1-3+自适应) → `write`(StrokeAnimation/StrokeTrace/TraceCanvas) → `speak`(朗读)。
- `practice(skill, correct, 1, difficulty)` 已透传难度给 SRS。
- `skill = hanzi:${hanzi.c}`，与 SRS/adaptChain 打通。

**出题引擎**（`hanziQuestions.ts`，7 题型）：拼音/选字/组词/听音选字/部首/笔画数/形近字，`makeHanziMixedQuestion` 随机抽，`makeHanziQuestion(target, difficulty)` 按难度 1/2/3 分配题型。

**字库**（`src/data/hanzi.ts`，`HANZI_DATA` 300 字）：字段 `c/p/pd/tone/radical/strokes/origin/evolve/words/sentence/level/freq`，已按 level→freq 排序。

**索引与推荐**（`hanziIndex.ts`）：`nextHanzi` 顺序遍历找首个 `mastery['hanzi:'+c].lv<1`。

**基础设施**：SRS（`srs.ts` 难度感知）、adaptChain（`hanzi:` 类别）、TTS（`speak` + 多音字纠音）、真实笔顺（`public/data/hanzi-strokes.json`）、PWA 离线预缓存、ai/guard 儿童护栏、i18n 双语。

## 3. 差距分析（Gap Analysis）

| 维度 | 现状 | 专业标杆 | 差距 | 杠杆 |
|---|---|---|---|---|
| 字理分类 | `origin` 纯文字，无结构化六书类型 | 洪恩按象形/形声分类讲 | **无法按字理组织教学、无法出六书辨析题** | ① |
| 部件关系 | `radical` 单一部首，无拆分/派生关系 | WaniKani 依赖图、基本字带字 | **无法可视化字族、推荐无字理逻辑** | ② |
| 字形演变 | `evolve` 纯文字描述 | 洪恩演变动画、字源图 | **"演变" Tab 只有文字，缺视觉冲击** | ③ |
| 推荐排序 | 线性遍历 level→freq | 依赖图驱动（先部件后合体） | 推荐不遵循"独体先于合体" | ②+DDA |
| 题型 | 7 类，无字理题 | 六书辨析、部件拼字 | 缺"用字理考查"的题型 | ①② |

**结论**：识字模块的下一个专业跃迁 = **把"字理"从文字描述升级为结构化数据 + 可视化 + 可出题 + 可驱动推荐**。

## 4. 三大增强杠杆·详细设计

### 4.1 杠杆① 六书字理分类

**目标**：每个字带六书类型，支持「按字理浏览」「字理卡片讲解」「六书辨析题」。

- 数据：新增 `liushu: 'pictographic'|'ideographic'|'compound-ideographic'|'pictophonetic'`（象形/指事/会意/形声）。形声字额外记 `phonetic`（声旁）与 `semantic`（形旁）。
- 交互：
  - `know` 步骤新增「字理徽章」（🖼象形 / 👆指事 / 🧩会意 / 🔊形声），点击弹出该类字理的通俗讲解 + 同类字推荐。
  - 字墙支持按六书筛选（象形字优先展示字源图，视觉最友好）。
- 出题：新增 `makeHanziFormationQuestion(target)` —「'休'是怎么造出来的？」四选一（人+木=靠树休息=会意）。

### 4.2 杠杆② 部件派生图（基本字带字 / precursor 依赖图）

**目标**：把"独体字→合体字"的构字关系固化为图，驱动可视化字族网络 + 依赖图推荐 + 部件拼字题。

- 数据：
  - `components: string[]`——该字的构成部件（如 `清` = `['氵','青']`）。
  - `derived: string[]`——以本字为部件派生出的字（如 `青` → `['清','晴','请','睛','情']`）。
  - 由此构成有向图：`基本字 --部件--> 合体字`。
- 交互：
  - 新增/强化「字族树」视图：中心是基本字（如"青"），辐射出派生字，点击任一字进入学习流。复用现有 `family` Tab 升级为图可视化（SVG 力导向或径向布局，儿童友好大字号）。
  - `know` 步骤显示"这个字由 X + Y 组成"，X/Y 可点击跳转。
- 推荐升级：`nextHanzi` 增加"依赖优先"策略——优先推荐其 `components` 已全部掌握（`lv≥1`）的字，实现"先学部件再学合体"。
- 出题：`makeHanziComponentQuestion(target)` —「'请'去掉'讠'是什么字？」或「'氵'+'青'=？」。

### 4.3 杠杆③ 真·字形演变（程序化 SVG 动画）

**目标**：把 `evolve` 从纯文字升级为**可视演变**，第一期零版权风险、离线可用。

- 数据：`glyphs?: { jiagu?, jin?, xiaozhuan?, kai }`——各阶段 SVG path（有则用真实字形，无则回退到 hanzi-writer 楷书 + 风格化滤镜表现古体）。
- 交互：`HanziEvolve` 组件升级为**时间轴动画**：甲骨文→金文→小篆→楷书四帧，用 hanzi-writer 楷书作 base，通过 SVG `stroke-dasharray` 描边动画 + 手绘风格滤镜（feTurbulence 位移）表现"越古越像画"的渐变；配 TTS 讲解每个阶段。
- 降级：首批 300 字若无真实古体 SVG，用"楷书描边逐笔重现 + 字源文字 `origin`/`evolve`"组合，视觉上仍显著优于纯文字。

## 5. 数据模型设计

**新增独立数据文件**（不污染现有 `hanzi.ts`，通过字 key 关联）：

`src/data/hanziEtymology.ts`
```ts
export type Liushu =
  | 'pictographic'        // 象形：日、月、山、水
  | 'ideographic'         // 指事：上、下、一、本
  | 'compound-ideographic'// 会意：休、明、林、看
  | 'pictophonetic';      // 形声：清、妈、江、426

export interface HanziEtymology {
  c: string;                 // 关联字（与 HANZI_DATA.c 对齐）
  liushu: Liushu;            // 六书类型
  components: string[];      // 构成部件，如 ['氵','青']
  derived?: string[];        // 以本字为部件的派生字，如 青→['清','晴',...]
  phonetic?: string;         // 形声字声旁（liushu==='pictophonetic' 时）
  semantic?: string;         // 形声字形旁
  glyphs?: {                 // 字形演变 SVG（缺省则回退楷书程序化动画）
    jiagu?: string;          // 甲骨文 path
    jin?: string;            // 金文
    xiaozhuan?: string;      // 小篆
    kai: string;             // 楷书（必有，可复用 hanzi-writer）
  };
  storyHint?: string;        // 字理助记一句话（喂给 AI/直接展示）
}

export const HANZI_ETYMOLOGY: Record<string, HanziEtymology>;
```

**索引/查询层**（新增 `src/lib/hanziEtymology.ts`）：
```ts
getEtymology(c: string): HanziEtymology | undefined;
getByLiushu(t: Liushu): string[];              // 按六书取字
getDerived(c: string): string[];              // 派生字
getComponents(c: string): string[];          // 部件
buildFamilyGraph(root: string): FamilyNode;   // 构字族树（供可视化）
recommendByPrereq(mastery, level): string;    // 依赖图驱动推荐（喂给 nextHanzi）
```

**为什么独立文件而非扩展 `HanziEntry`**：字源数据获取/校订是渐进的（先 128 核心字，再 300，再 500），独立文件可增量补充、按需懒加载，且不影响现有 300 字数据的稳定性；查询层用 `Record` O(1) 命中。

## 6. 数据抓取 / 生成脚本设计

`scripts/fetch-hanzi-etymology.mjs`（参照现有 `fetch-hanzi-strokes.mjs` 的并发抓取范式）：

1. 拉取 **Make Me a Hanzi** 的 `dictionary.txt`（每行一个 JSON：`{character, decomposition, etymology, radical, ...}`）。
2. 对 `HANZI_DATA` 的 300 字逐一匹配：
   - `etymology.type` → 映射为 `liushu`（pictographic/ideographic/pictophonetic/…）。
   - `decomposition`（IDS，如 `⿰氵青`）→ 解析出 `components`。
   - 形声字 `etymology.phonetic/semantic` → `phonetic/semantic`。
3. 反向构建 `derived`：遍历所有字的 `components`，把"谁用了我"聚合回基本字。
4. 生成 `src/data/hanziEtymology.ts`（或 `public/data/hanzi-etymology.json` + 运行时懒加载，与笔顺数据一致，走 PWA 预缓存 + stale-while-revalidate）。
5. **人工校订闸门**：脚本产出后标注置信度低的条目（如 etymology 缺失、IDS 解析失败），人工过一遍首批核心字，确保儿童向准确性（六书判定有学术争议，需教研校订）。

> 版权：Make Me a Hanzi 为 Arphic 宽松许可，字源文本可用；真实古体字形图（甲骨文等）第一期不引入，规避风险。

## 7. 信息架构与交互设计

**不新增顶层路由**（遵循"一入口"原则），在识字模块内升级：

| 现有入口 | 升级动作 |
|---|---|
| `evolve`（演变 Tab） | `HanziEvolve` 升级为字形演变时间轴动画（杠杆③） |
| `family`（字族 Tab） | 升级为**字族树可视化**（杠杆②依赖图） |
| `radical`/`magic` | 复用，`components` 数据可增强"部首魔法"玩法 |
| `HanziLearn.know` 步骤 | 加"字理徽章"（杠杆①）+"由 X+Y 组成"（杠杆②）+ 演变入口（杠杆③） |
| 字墙（level1/2/3） | 加"按六书筛选"chip（杠杆①） |

**核心交互（know 步骤增强示意）**：
```
┌─────────────────────────┐
│         清  qīng         │  ← 大字 + 拼音（已有）
│  🔊形声  [听字理]         │  ← 六书徽章(①) + TTS
├─────────────────────────┤
│  由  氵(水) + 青(声)  组成 │  ← 部件拆解(②)，可点
│  同族: 晴 请 睛 情        │  ← derived(②)，可点跳转
├─────────────────────────┤
```

## 8. 与现有系统集成点（复用而非新建）

| 系统 | 集成方式 |
|---|---|
| **SRS**（`hanzi:${c}`） | 六书辨析题/部件拼字题的正误照常 `practice(skill, correct, 1, difficulty)`；依赖图可为"到期基本字"关联唤醒其派生字复习 |
| **adaptChain**（`hanzi:` 类别） | 新题型错误计入 `getWeakTypes('hanzi:...')`；`recommendByPrereq` 与 DDA 心流区协同（部件未掌握时不推合体字） |
| **TTS `speak`** | 字理讲解、演变各阶段、部件读音朗读，复用多音字纠音 |
| **AI 字理故事**（`hanziStoryTask`） | 喂入结构化 `liushu/components/storyHint`，故事更准确（形声字讲"声旁表音、形旁表义"） |
| **PWA** | `hanzi-etymology.json` 加入预缓存清单（`scripts/gen-sw-precache.mjs` 派生），离线可用 |
| **ai/guard** | AI 生成的字理内容沿用儿童安全护栏 |
| **i18n** | 六书类型名、字理讲解、UI 文案建双语 key（象形/pictographic 等） |

## 11. 风险与验收标准

**风险：**
1. **六书判定学术争议** → 首批核心字人工校订，脚本标注低置信条目。
2. **字源图版权** → 第一期程序化 SVG，不引入真实古体图。
3. **依赖图推荐与线性 freq 排序冲突** → recommendByPrereq 作为 nextHanzi 的**优先层**，无满足项时回退现有 freq 遍历，保证不退化。
4. **数据体积** → json 懒加载 + PWA 预缓存，首屏不受影响（与笔顺数据同策略）。

**验收标准（DoD）：**
- [ ] 300 字中 ≥128 核心字有完整六书/部件/派生数据，单测校验字段完整性。
- [ ] `know` 步骤展示六书徽章 + 部件拆解，派生字可点击跳转。
- [ ] 演变 Tab 呈现四阶段动画（真实/程序化），配 TTS 讲解。
- [ ] 字族树可视化可交互，中心字辐射派生字。
- [ ] 新增 2 类字理题型纳入混合出题，正误计入 SRS/adaptChain。
- [ ] nextHanzi 遵循"部件优先"，无满足项回退不报错。
- [ ] 全量门禁（tsc -b --force / vite build / test）绿，线上冒烟通过。

## 附：一句话结论

识字模块已是"能用且好用"的第一梯队产品，本方案的专业增强聚焦一件事——**把"字理"从文字描述升级为「结构化六书 + 可视化部件派生图 + 字形演变动画 + 可出题 + 可驱动推荐」的完整闭环**，全部复用现有 SRS/DDA/TTS/PWA 基础设施，分 P1(数据)→P2(组件)→P3(题型+推荐) 三步落地。等你确认方向后即可进入编码实现。
