### 4.2 设计

**玩法池 18 种**（三核心各 6 种），覆盖「认 / 学 / 读 / 写 / 练 / 测」六类交互形态：

| 模块 | band1（辨认感知） | band2（应用） | band3（迁移/速度） |
|---|---|---|---|
| 识字 | 象形动画 · 听音选字 · 生活场景 | 描红写字(慢) · 组词拼装 | 偏旁归类 |
| 词语 | 看图选词 · 听音选词 | 词语拼图 · 句子填空 | 词语分类 · 反义配对 |
| 数学 | 数物计数 · 比大小 | 算珠加法 · 数轴跳跃 | 速算冲关 · 应用题小故事 |

**每个玩法带两个正交标签**：
- `band`（难度带 1–3）→ 与 `DifficultyLevel` 语义对齐，**band 上限 = 孩子当前 level，绝不越带**
- `load`（认知负荷 1–3）→ 用于交替节律，避免连续重负荷（TCM 2026 实证）

**两个 API**：

```ts
pickNextMode({ module, level, recent?, exclude?, lastLoad?, slowUsed?, seed? }): PlayMode
buildSessionPlan({ module, level, length?, recent?, seed? }): PlayMode[]
```

**六级降级链**（自上而下逐级收窄，保证任何入参都有返回值、绝不抛错）：

```
1. 带内 + 本节不重复 + 近期不重复 + 慢玩法配额 + 负荷交替   ← 理想态
2. 放宽负荷交替          （玩法池偏重负荷时）
3. 放宽跨节 recent       （历史记录很长时）
4. 放宽慢玩法配额        （难度带把池压得很窄时）
5. 只守难度带            （宁可本节内重复，也不越带）
6. 任意玩法              （level 被误传为 0 等极端情况）
```

> **关键设计权衡（第 5 级）**：宁可在一节课内重复一个已玩过的玩法，
> 也绝不把孩子推到超出当前能力带的玩法上 —— 难度越界带来的是**挫败感**，
> 玩法重复只是轻微的**新鲜感折扣**。这是把 MDPI SLR 2026「谨慎标定挑战难度」
> 与洪恩「过度游戏化副作用」反面教材落到代码里的具体决策。

**其他约束**：
- **确定性可测**：随机数由注入 seed 驱动的 mulberry32 生成，无 `Math.random`，
  单测完全可复现，家长复盘时能重放同一节课的玩法序列。
- **疲劳控制**：慢玩法（书写 / 跟读）每节课最多 1 次，防止单节课拖长。
- **节奏**：一节课默认 5 题（对齐洪恩「每 5 字一单元」、宝宝巴士「一课一练」），
  收尾一题允许触及当前最高难度带，给「我做到了」的成就感。
- **无竞争性**：玩法池文案经测试断言不含「排行 / 排名 / 对战 / PK / 惩罚 / 扣分 / 失败」。

### 4.3 自测暴露并修复的 2 个真实缺陷（非测试适配）

| # | 缺陷 | 根因 | 修复 |

| 2 | 一节课内可能重复同一玩法 | 原来只按 `AVOID_REPEAT_WINDOW=2` 窗口去重，窗口外的旧玩法可重现 | 新增 `exclude`（本节课已用，强约束）与 `recent`（跨节，软约束）双通道，并重构降级链 |
