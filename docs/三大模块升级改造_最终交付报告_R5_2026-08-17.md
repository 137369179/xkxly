## 三、三大模块升级改造方案

> 每模块均按「现状分析 / 改造目标 / 具体实施内容 / 验收标准」四段呈现。

### 3.1 识字模块（hanzi）

**现状分析**
- 功能最丰富（20 个文件），但早期「判定对错」类练习未回写学习记录，SRS 无法根据表现调整复习节奏（🔴 P0）。
- 部分子组件不接受「目标字」入参，深链只能切入口 tab，无法直达具体汉字。

**改造目标**
- 闭环学习数据，使识字练习可驱动 SRS 复习与勋章发放。
- 支持从错题本 / 薄弱点一键直达具体汉字的描红或组词专项。
- 消除非 null 断言与 i18n 死 key，达到生产级稳定性。

**具体实施内容**
- R1：所有「判定对错」练习接入 `useStore.practice(...)`；新增 `src/store/closure.test.ts`（43 用例）固化闭环。
- R3：`HanziPage` 解析深链 `stroke:<字>` / `build:<字>`，下发给 `HanziStrokeWriter`（`hanzi` 直接预选）与 `WordBuilder`（新增 `initialChar` prop + 一次性 `seededRef` 守卫）。
- R2/R4：i18n 收口；`skillRouting` 中 `hanzi:*` 命名空间与 `SUB_LABELS` 单一事实源。

**验收标准**
- ✅ 任意识字练习完成后，`practice()` 被调用且 `progress` 数据更新；SRS 隔日复习可见。
- ✅ 访问 `#/hanzi/stroke:水` 直接进入「水」描红并预选；`seededRef` 保证仅首挂载预选一次。
- ✅ 识字相关组件 `tsc` 0 error、ESLint 0 error、无 i18n 死 key（locales.test 防回归）。

### 3.2 英语模块（letters + words + pinyin）

**现状分析**
- 字母描红 / 自然拼读 / 拼音拼读三大子系统各自独立，缺乏统一的薄弱点→专项训练路由。
- 与识字类似，早期练习未回写学习记录；深链无法预选具体字母。

**改造目标**
- 建立英语子系统统一的 skill→专项训练路由（含深链参数约定）。
- 错题本可按「原因」聚类并一键回到对应英语专项。
- 全模块非 null 断言清零、i18n 完整。

**具体实施内容**
- R1：letters/words/pinyin 的「判定对错」练习全部接入 `practice()`。
- R2：新增 `src/lib/skillRouting.ts`（`letter:*`/`word:*`/`pinyin:*` 命名空间 + `openTraining` + `SUB_LABELS`）、`useTrainingTarget` hook、`TrainingBanner`；ParentPage 薄弱点加「去练习」。
- R3：`LettersPage` 解析 `trace:<A>`，下发给 `LetterTrace`（新增 `initialLetter` prop）与 `LetterStudy`（新增 `initialUpper` prop）；新增 `LetterTrace.test.tsx` 固化预选。
- R4：训练横幅 / 错因 Tab 走 i18n（`training.banner` / `wrongbook.causes.*`）。

**验收标准**
- ✅ 英语薄弱点面板点击「去练习」可跳转到对应专项且预选目标字母/音节。
- ✅ 错题本「🧩 按原因」tab 中英语错因分组可「去练习」直达。
- ✅ 英语三子系统 `tsc` 0 error、ESLint 0 error、深链预选单测通过。

### 3.3 数学模块（numbers + logic + 拼图组件）

**现状分析**
- 数学覆盖面广（数感/分数/钱币/十格/跳数/数独/迷宫），但**正确性敏感**的拼图组件 `SlidingPuzzle / SudokuEasy / MiniSudoku` 大量使用 `!` 非 null 断言（8/15/10 处），且无任何单元测试保护。
- 这些组件经 `FunPage` 懒加载进入生产，断言一旦因数据异常失效即可能崩溃。

**改造目标**
- 为三个数学拼图组件补齐**玩法单元测试**（判定规则、可解性、拉丁方不变量）。
- 在不改变任何玩法行为的前提下，安全移除全部非 null 断言。
- 导出纯逻辑函数（genGrid/isSolved/isCorrect/genBoard）提升可测试性与长期可维护性。

**具体实施内容（R5 本轮）**
- `SlidingPuzzle.tsx`：新增 `cellAt()` 边界安全读取助手；`genGrid/findBlank/getMoves/isSolved` 改为可选链 + 守卫，并 `export` 供测试；新增 `SlidingPuzzle.test.tsx`（8 用例：结构/邻居规则/终局判定/渲染冒烟/滑动后空格移动）。
- `SudokuEasy.tsx`：`PUZZLES/SOLUTIONS/isCorrect` 改为 `?? []` 兜底并 `export`；theme 的 keyof 索引去掉 `!`；新增 `SudokuEasy.test.tsx`（5 用例：数据完整性/正解判定/填错判定/渲染冒烟）。
- `MiniSudoku.tsx`：`genBoard` 导出，`base[r]?.[c]` 等改为可选链 + `?? ''`；`checkWin/fillCell` 加行守卫；新增 `MiniSudoku.test.tsx`（5 用例：拉丁方不变量/谜面为解子集/挖空数/渲染冒烟）。

**验收标准**
- ✅ 三个组件 `tsc` 0 error、ESLint 0 error、玩法单测全绿（18 用例）。
- ✅ `no-non-null-assertion` 全局再降 70（524→454），且 lint budget 门禁通过。
- ✅ 行为等价：所有 `!` 替换为 `?.`+兜底或类型守卫，未改动任何游戏规则；`vite build` 成功。

## 四、竞品研究驱动的升级要点（R4 调研，本轮复用）

调研对象：**识字**——洪恩识字、帮帮识字、宝宝巴士汉字；**英语**——叽里呱啦、伴鱼绘本、ABC Reading；**数学**——宝宝巴士数学。提炼 8 条跨品类设计原则，已映射进本方案：

1. **游戏化闭环 + 即时正反馈**：星星/勋章即时奖励（已落地 `practice()` 回写 + 16 枚勋章体系）。
2. **重复与间隔复习（SRS）**：按正确率/星数调度复习（已由 `useStore.practice` 驱动的复习队列支撑）。
3. **错误即学习**：错题本按根因聚类、可一键回到专项（R2 `wrongCluster` + R3 深链直达）。
4. **情境化与多模态**：字源动画、语音、描红多通道输入（hanzi 字源动画 / 英语语音 / 数学拖拽）。
5. **渐进难度与薄弱点路由**：基于表现自动推送下一关（R2 `skillRouting` + `useTrainingTarget`）。
6. **家长可视与参与**：薄弱点面板「去练习」（ParentPage）。
7. **低龄友好的视觉与交互**：果冻粉设计系统、大点按区域、动效克制。
8. **防挫败设计**：预选/提示/宽松判定，避免幼儿卡关（深链预选、错因聚类降低重复错误）。
